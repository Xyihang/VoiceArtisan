# GUIDE-1 · 应用内「教程」页面规格

> 状态：已实现（v1.1.3）｜规格作者：xiyihang ｜ 适用范围：`frontend/src/pages/GuidePage.tsx`

## 1. 概述

### 1.1 背景
「设置」页有 11 个分区、约 45 个字段，每个字段的 hint 只有一句话。用户遇到
`VRAM_INSUFFICIENT`、隧道连不上、质检怎么开、0.6B 与 1.7B 怎么选时，只能去翻
`docs/` 下的七八个 Markdown 文件。需要在**应用内**给出一份可搜索、可跳转、
和界面字段一一对应的中文教程。

### 1.2 目标
- 新增独立页面「教程」，位于左侧导航栏**最下面**（主导航之下、版权区之上，有一条分隔线）。
- 覆盖「设置」页**全部 11 个分区、全部可改字段**：字段作用 + 取值建议 + 典型操作步骤 + 踩坑提示。
- 每个分区提供「打开设置对应分区」按钮，直接落到 `#/settings?s=<id>`。
- 提供常见错误码速查表（错误码 → 界面提示 → 处理办法）。
- 只读页面：不新增任何请求、不写配置、不触发模型加载（纯静态数据）。

### 1.3 范围
- **做**：新页面、导航项、命令面板入口、深链接、错误速查、样式。
- **不做**：不做富文本/Markdown 渲染引擎；不接入在线文档；不改设置页本身的字段与文案；
  不做多语言（仅中文）。

## 2. 用户故事

| 角色 | 故事 |
| --- | --- |
| 首次使用者 | 我想知道「混合模式」到底是什么，以便决定选哪个运行模式。 |
| 2GB 显卡用户 | 我想知道 0.6B 到底需要多少显存、跑不动时有哪些替代方案。 |
| 云端用户 | 我想知道 `base_url` 该填公网地址还是隧道地址、自签证书为什么连不上。 |
| 排障用户 | 我看到「本地显存不足」，想直接查到原因与四条处理路径。 |

## 3. 功能需求

### 3.1 功能清单

| 模块 | 优先级 | 说明 |
| --- | --- | --- |
| 侧栏「教程」入口 | P0 | 固定在导航栏最下方，带分隔线；当前页高亮 |
| 分区锚点导航 | P0 | 左侧列（208px，sticky）列出 11 个分区，滚动联动高亮 |
| 全文搜索 | P1 | 搜索分区标题/字段名/正文，命中分区保留、其余隐藏并 `<mark>` 高亮 |
| 字段说明表 | P0 | 字段名、作用、建议值三列；与设置页标签逐字一致 |
| 操作步骤 | P0 | 有序列表，编号步骤 |
| 踩坑提示 | P0 | 警示块（`InlineNote`），每分区 1–3 条 |
| 去设置按钮 | P0 | `跳到设置` → `#/settings?s=<id>`，落到对应分区 |
| 错误码速查 | P1 | 9 个高频错误码：症状 / 原因 / 处理 |
| 命令面板入口 | P2 | `Ctrl/Cmd+K` → 「页面跳转 · 教程」 |

### 3.2 详细规格

#### 3.2.1 导航项
- 路由 id：`guide`；标题「教程」；图标 `BookOpen`。
- 位置：`ROUTES` 数组之外单独渲染，置于 `.rail__nav-bottom`（`margin-top:auto` + 上边框）。
- 命中当前路由时 `aria-current="page"`，与主导航同款样式。
- 窄屏（≤900px）折叠为纯图标，`title` 保留文字。

#### 3.2.2 分区定义（顺序与设置页一致）

| id | 标题 | 对应设置分区 |
| --- | --- | --- |
| `start` | 五分钟跑通 | （无「跳到设置」，纯快速开始） |
| `mode` | 运行模式 | `#settings-mode` |
| `cloud` | 云端连接 | `#settings-cloud` |
| `tunnel` | SSH 隧道 | `#settings-tunnel` |
| `asr` | 语音转文字 | `#settings-asr` |
| `warmup` | 模型预热 | `#settings-warmup` |
| `engines` | 引擎与模型 | `#settings-engines` |
| `local` | 本地模型 | `#settings-local` |
| `qc` | 内容质检 | `#settings-qc` |
| `text` | 文本处理 | `#settings-text` |
| `defaults` | 默认参数 | `#settings-defaults` |
| `license` | 授权与数据 | `#settings-license` |
| `errors` | 常见错误速查 | （无「跳到设置」） |

合计 13 个分区：设置页 11 个分区全部覆盖，另加「五分钟跑通」与「常见错误速查」两张辅助卡片。

#### 3.2.3 分区内容结构

```ts
type GuideSection = {
  id: SectionId;          // 与设置页 SectionId 同名
  label: string;          // 分区标题
  icon: LucideIcon;
  summary: string;        // 一句话作用
  steps?: string[];       // 操作步骤（有序）
  fields: { name: string; desc: string; suggest?: string }[];
  tips?: string[];        // 踩坑提示
  faq?: { q: string; a: string }[];
};
```

- `fields[].name` 必须与设置页 `Field label` 完全一致（含单位与括号），保证「搜索同一个词能找到」。
- 建议值使用配置默认值，来源 `config/config.yaml`。

#### 3.2.4 搜索
- 触发：输入即过滤（无需回车），右上角清除按钮。
- 匹配范围：`label` + `summary` + `steps` + `fields[].name/desc/suggest` + `tips` + `faq`。
- 无命中：显示空状态 + 「清除搜索」按钮 + 关键词建议。
- 高亮仅对分区标题与字段名生效（避免正文里 `1` 之类的单字符全亮）。

#### 3.2.5 滚动联动
- 复用设置页实现：`IntersectionObserver`（`rootMargin: '-96px 0px -58% 0px'`）+ rAF 节流的 `scroll` 校正，
  滚到底部时落到最后一个可见分区。

#### 3.2.6 去设置
- 点击后 `window.location.hash = '#/settings?s=<id>'`；
- 设置页已存在 `readAnchorParam()` 读取 `?s=` 并滚动到分区，无需改动设置页。

## 4. 非功能需求

| 项 | 要求 |
| --- | --- |
| 首屏渲染 | 纯静态数据，无网络请求；切换页面 < 100ms |
| 体积 | 页面代码 ≤ 40KB 源码，`gzip` 后 dist 增量 ≤ 15KB |
| 无障碍 | 导航 `aria-label`；搜索 `aria-label`；空状态 `role="status"`；焦点可见 |
| 响应式 | ≥1240px 双列；<1240px 单列且导航折叠为下拉；≤900px 侧栏图标模式 |
| 一致性 | 只用现有 CSS 变量与 `SectionCard` / `InlineNote` / `Field` 组件，不新增设计 token |

## 5. 验收标准

- [ ] 侧栏最下方出现「教程」，点击进入 `#/guide`；刷新后仍停留在该页。
- [ ] 13 个分区全部存在；其中设置页的 11 个分区顺序与设置页一致。
- [ ] 设置页出现的每一个可改字段，都能在教程里通过同名关键词搜到（抽样 15 个字段逐一验证）。
- [ ] 每个分区的「跳到设置」都能落到设置页对应分区。
- [ ] 搜索「显存」「隧道」「质检」「0.6B」均能命中正确分区。
- [ ] 滚动时左侧导航高亮跟随；滚到底部停在最后一个分区。
- [ ] 命令面板 `Ctrl/Cmd+K` 输入「教程」可跳转。
- [ ] `npm run build`（`tsc --noEmit` + vite build）零错误、零 TypeScript 告警。
- [ ] 教程页自身不发起任何请求（不新增 fetch/WebSocket；只剩 AppProvider 既有的健康轮询）。
- [ ] 深色/浅色主题下无对比度问题，无横向滚动条。

## 6. 风险与依赖

| 风险 | 处理 |
| --- | --- |
| 设置页字段文案改动后教程不同步 | 教程 `fields[].name` 与设置页标签同名，改字段时必须同步改本规格与教程；抽样测试通过关键词断言 |
| 教程内容与真实默认值漂移 | 建议值全部取自 `config/config.yaml`；该文件改动时同步 |
| 页面变长导致锚点导航失准 | 复用设置页已验证的 IntersectionObserver + 几何校正实现 |
